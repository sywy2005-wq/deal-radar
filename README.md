# Deal Radar v1

面向 **ST 3ST LW JKT（KX0493，L 码）** 的最小可用价格雷达。项目坚持“没有证据就没有价格”：仓库不含示例报价，未配置的数据源不请求，未通过校验的数据不落入历史。

## 已完成

- 简洁的移动端/桌面端页面，展示目标、数据源状态、已验证报价历史。
- 按输入顺序叠加百分比折扣、满减、立减；金额全程以“分”计算。
- 报价校验：精确匹配货号 `KX0493`、尺码 `L`、币种 `CNY`，检查正价格、来源域名和新鲜度。
- 只有完成实时上游拉取且校验通过的记录，才原子写入本地 JSON 历史并去重。
- Node.js 24 原生测试与 GitHub Actions CI，不依赖第三方运行时包。

## 运行

```bash
nvm use 24
npm install
npm test
npm start
```

打开 <http://localhost:3000>。默认没有数据源、没有价格，也不会声称存在历史最低价。

## 真实数据源接入

v1 提供一个**显式配置的 JSON 适配器**。仅当运营方核验数据授权、接口语义和商品链接后，才可设置：

```bash
QUOTE_SOURCE_URL=https://trusted-shop.example/api/kx0493-l \
QUOTE_SOURCE_NAME='授权零售商' \
QUOTE_SOURCE_ENABLED=true \
QUOTE_MAX_AGE_MINUTES=30 npm start
```

上游响应契约：

```json
{
  "sku": "KX0493",
  "size": "L",
  "currency": "CNY",
  "price": 699,
  "observedAt": "2026-10-02T11:50:00Z",
  "productUrl": "https://trusted-shop.example/products/KX0493"
}
```

`productUrl` 必须与 API 地址同源。`POST /api/quotes/refresh` 每次实时请求上游；超时、HTTP 错误、过期或字段不匹配都只报告错误，不保存数据。计算器结果永不写入历史。

## v1 验收标准

1. Node.js 24 下 `npm run check` 与 `npm test` 全部通过，CI 对 push 与 PR 执行相同检查。
2. 初次启动页面显示“尚无真实报价”，历史为空且不出现“历史最低价”数值。
3. 未设置 `QUOTE_SOURCE_URL` 时刷新不产生外网请求；配置但未设置 `QUOTE_SOURCE_ENABLED=true` 时也不请求。
4. 真实响应只有同时满足目标身份、CNY 正价格、同源链接和时效要求才入库；相同观测记录不重复。
5. 优惠计算的应用顺序可解释，未启用优惠不生效，非法金额/折扣被拒绝；计算结果明确标为非报价。

## 当前限制

- JSON 文件适合单实例 v1；多实例部署前需迁移到带唯一约束和事务的数据库。
- 目前没有任何经过授权并验证的生产数据源，因此仓库及默认页面**没有真实价格和历史最低价结论**。
