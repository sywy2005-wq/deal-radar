# Deal Radar v1

目标商品：**ST 3ST LW JKT / KX0493 / L 码**。默认没有生产数据源或价格。
当前版本提供字段校验、价格计算与单实例历史存储，不代表已经接入真实平台或经过结账核验。

## 运行

需要 Node.js 24。运行 `npm ci`、`npm run check`、`npm test`、`npm start`，打开 http://localhost:3000。
CI 使用相同检查；运行时没有第三方依赖。

## 报价状态与历史展示

- `field_checked` 仅说明货号、尺码、币种、金额、链接和时间通过字段检查，不证明数据来源可信或结账价格成立。
- 库存、颜色、运费、地区、数量、优惠资格或价格口径缺失时，记录显示“待核验”，不参加最低值比较。
- 完整记录按来源、货号、尺码、颜色、币种、地区、数量、优惠人群及价格口径分组。
- 每组只展示“已采集记录中的最低价”，同时显示记录数与采集起止时间，不声称全网或商品全生命周期历史最低价。
- 合计为来源报告的优惠后商品金额加运费，仍需真实结账核验。当前 `hasVerifiedHistory` 始终为 false；`hasObservedHistory` 表示已采集记录存在。
- 旧历史缺少购买条件时可查看，但不参与最低值比较。

## 接入契约

数据源必须经过运营方核验授权、零售商身份、字段语义和商品链接后才能显式启用。
仅设置 `QUOTE_SOURCE_URL` 不会请求网络；还需要 `QUOTE_SOURCE_ENABLED=true`。
`QUOTE_SOURCE_NAME` 为显示名称；`QUOTE_MAX_AGE_MINUTES` 默认 15，必须为有限正数。
接口和商品链接必须同源，使用无 URL 凭据的 HTTP(S) 地址。当前适配器只支持配置的 JSON 源，不是京东或天猫官方接入。

上游基础字段：

| 字段 | 要求 |
| --- | --- |
| sku / size / currency | KX0493 / L / CNY |
| price | 元，正金额，最多两位小数；拒绝布尔值、空值与超范围值 |
| observedAt | 包含明确时区的日期时间字符串；不得超期或来自未来 |
| productUrl | 与接口同源的商品链接 |

上游购买条件字段：

| 字段 | 要求 |
| --- | --- |
| color | 精确颜色标识 |
| stock | in_stock / out_of_stock / unknown；只有 in_stock 可比较 |
| shipping | 元；零明确表示免运费，缺失表示未知 |
| shippingRegion | 报价适用的收货地区标识 |
| quantity | 正整数；当前目标只比较单件报价 |
| offerEligibility | public / verified_account / unknown |
| eligibilityKey | 优惠适用人群标识；不同会员或优惠条件使用不同标识 |
| couponCoverage | complete / partial / unknown |
| priceBasis | payable_item_price / item_price / unknown；只有明确优惠后的商品金额可比较 |

只有基础校验通过才保存。条件缺失的记录可以保存用于追溯，但价格状态为 needs_verification。
非法金额、无效链接、未来或过期时间直接拒绝。
内部金额为整数分，金额上限为 1,000,000,000,000 分；总金额也受此限制，百分比使用整数基点计算。
计算器为手动估算商品金额，没有自动识别优惠资格，也不包含未知运费，计算结果永不入历史。

## 持久化与验收

JSON 存储仅支持单实例。写临时文件后原子替换，重复观测幂等；去重包含购买条件。
一次写入失败返回错误并保留已有历史，后续排队写入可以继续；临时文件尽力清理，失败不静默吞掉。
多实例及长期采集前需迁移到带唯一约束和事务的数据库，并实现备份恢复。

本次修复验收：
1. 一条不完整报价不会产生最低值汇总；完整记录明确标出采集区间和数量。
2. 不同来源、颜色、地区和优惠适用人群分组；缺货、未知运费或未知优惠资格不参加比较。
3. 金额拒绝布尔值、空值、多余小数和溢出；折扣四舍五入到整数分。
4. 写入失败保留旧记录，后续写入恢复；并发重复请求不会重复入库。
5. 初次启动没有价格；未启用源不请求网络；所有 JavaScript 语法检查和回归测试通过。

## 持续采集与接入状态（本轮新增）

默认读取 `config/sources.json`，京东与天猫都是待接入条目，不会请求网络。
外部配置可通过 `QUOTE_SOURCES_FILE` 指定，支持多个授权 JSON 接口。
配置需含唯一 id、显示名称、HTTPS 接口 url、enabled、reviewStatus、reviewEvidence；
只有 enabled=true、reviewStatus=verified 且 reviewEvidence 非空才启用。
reviewEvidence 是运营方的核验记录，不能单靠该字段证明真实价格。

商品链接默认与接口同源；官方接口与商品站点域名不同时，运营方必须显式配置
`allowedProductOrigins`，例如 HTTPS origin 数组。禁止用通配符自动信任任意域名。
凭据使用 `tokenEnv` 指向环境 secret 名；公开状态 API 不返回接口地址、凭据或核验文件内容。

旧单接口方式仍支持，但显式启用还需设置
`QUOTE_SOURCE_REVIEWED=true` 和 `QUOTE_SOURCE_REVIEW_EVIDENCE`。
有效期上限十五分钟。上游重定向不跟随，响应限制 256 KiB。
字段校验通过的报价保留原始 JSON、响应摘要、解析器版本与接收时间，便于追溯。

`COLLECTION_ENABLED=true npm start` 开启调度；默认关闭。
SQLite 任务账本记录每十分钟计划任务、执行尝试和租约，重启后恢复未完成任务。
失败最多重试三次，间隔一／三／十分钟；超过十五分钟的旧计划记为错过，不补抓旧价格。
手动校验不计入计划成功率。并发刷新和定时执行共享一个运行队列，不同时抓取同一实例的数据源。
连续三次失败在页面显示提示；这不是外部消息通知。

页面显示来源阻塞原因与自动采集状态。七日指标仅计算已到十五分钟截止时间的计划任务，
并要求报价的购买条件完整；字段通过但条件缺失不算可用成功。
七日窗口至少有七天完整计划样本且及时可用率达到 95% 才标为采集指标达标。
此指标不代表结账价格已经核验，也不代替两个渠道各十五条结账对照验收。

部署需保持进程持续运行，并挂载持久目录保存 history.json、collection.sqlite 及 SQLite WAL 文件。
当前仍为单实例：报价 JSON 不支持多实例并发写入。CI 的 SQLite 与上游响应均为测试数据，
不算生产连续运行证据。源码未部署到公网，本轮未启用生产源。

真实来源核查记录见 [docs/source-evidence.md](docs/source-evidence.md)。
